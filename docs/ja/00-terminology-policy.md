# 日本語ドキュメントの用語ポリシー

このポリシーは、`docs/ja` を日本語として自然に読めるものにしつつ、CLI の出力や
契約を曖昧にしないための基準です。英語の単語を機械的に置き換えず、文脈で次の三つに
分けます。

## 用語の三つの扱い

- **英語のままにするもの**: 正確な CLI コマンドとフラグ、label 名、パス、固有名詞、
  `intent`、`packet`。これらは利用者がコマンド出力や契約で認識する語です。
- **自然な日本語の技術用語にするもの**: トランスポート、トポロジー、ロール、
  ワークスペース、パターン、セッションレイヤー、ホストリポジトリ、作業スライス。
- **通常の文章として訳すもの**: 新規/既存、同居、成熟度の注記、サポート対象の選択肢、
  永続化されたホスト状態、最初のプロンプト、自己完結。

「正典」は導入しません。データの truth は **正本となる定義**、actor の authority は
**権限** と表現します。文章中の `metadata branch` は **メタデータ用ブランチ** とし、
`main-metadata` のようなリテラルのブランチ名は変更しません。`self-contained` はページや
契約の一般的な説明では訳しますが、インストールやリリースで .NET の梱包用語を指す場合は
`self-contained` と日本語の説明を併記できます。

## 適用の進め方

この最初の pass は読者経路（索引、01、02、02a〜02e、03、04、07）に適用します。
`09`、次に `12`、最後に残る非リリースページを別の pass で扱います。リリースノートは
歴史的な記録であり、このポリシー適用の対象外です。

`JapaneseTerminologyGuardG613Tests` の manifest は、レビュー済みページだけを列挙する
rolling guard です。次の pass を完了したときにページを追加します。フェンス内のコード、
インラインコード、URL の宛先は検査しませんが、本文、表、リンクラベルは検査します。
例外をディレクトリやファイル種別で設けることはしません。
