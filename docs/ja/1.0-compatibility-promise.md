# intent-cli 1.0 compatibility promise

これは `intent-cli` 1.x line の compatibility commitment です。ledger の基準は
v0.11.1 surface であり、この文書は surface を変更しません。決定は
[ADR 0002](../adr/0002-one-dot-zero-compatibility-promise.md) に記録しています。

## 1.0 の意味

1.0 以降、MINOR release は compatible な capability を追加でき、PATCH release は
compatible な implementation を修正できます。covered surface の breaking change は
次の MAJOR release が必要です。ただし、下記の documented deprecation path は
1.x の間 old surface を保持したまま replacement を導入できます。

### Covered surface

promise が covered とする machine-consumed surface は、次に限ります。

- command name と flag name;
- automation が consume する JSON field name、field semantics、machine が emit する
  すべての `cause` value;
- exit code;
- durable record schema と許可された state transition。

prose、document layout、Markdown heading、unstructured diagnostic text は明示的に
**対象外**です。human-readable diagnostic は有用ですが automation API ではありません。

### Dependency が covered かを判断する

1. command/flag、JSON の field または machine が emit する `cause` value、exit code、durable
   schema/state transition のいずれかかを確認します。違うなら covered ではありません。
2. [compatibility ledger](1.0-compatibility-ledger.md) の entry を探します。registered
   command はすべて ledger に存在し、guard が omission を防ぎます。
3. entry の disposition に従います。dependent は prose を parse したり、undocumented
   field から state を infer したりしてはいけません。

machine-consumed JSON payload で実際に emit されるすべての `cause` value は、prose が
その value を現在 documented しているかにかかわらず covered です。coverage は
human-facing documentation の状態ではなく machine emission に従います。

## Deprecation rule

covered surface の変更には、次のすべてが必要です。

1. documented replacement;
2. automation が consume できる structured warning; および
3. 1.x line 全体で保持する alias。

removal は次の MAJOR release でのみ可能です。G623 は generalized durable judgment record の
stable-at-1.0 name として `judgment-wait` を出荷します。`operator-attention` は 1.x を通じた
`deprecate-with-alias` compatibility alias であり、machine JSON には `judgment-wait` と
`next-major` を示す `deprecation_warning` が追加されます。durable record schema と identifier は
変更しません。

## Pre-1.0 road

合意済みの順序は次のとおりです。

1. G611 link guard（independent）;
2. G612、この promise と ledger;
3. G623 による、完了済みの aliased `operator-attention` → `judgment-wait` rename;
4. named migration evidence がある場合だけの separately eligible legacy retirement;
5. herdr-only graduation MINOR; その後
6. 1.0 release preparation。

graduation には、4 team が各 30-day window 中 20 active days を示す live evidence、
zero unresolved transport-caused incidents、さらに fresh provisioning、restart と
headless resume、live-handoff EOF resubscribe、topology re-record/migration、routing recovery
の evidence が必要です。これは criterion の記録だけであり、herdr-only を
graduate したり PREVIEW qualifier を変更したりしません。

## Inventory boundary

ledger は role-pane-mapping compatibility read、runtime-state shape、packet-schema
variant、field alias を inventory します。inventory は removal の authority では
ありません。pre-1.0 retirement は ledger row が migration evidence を名指しする場合
だけ有効で、それ以外は 1.x を通じて retain します。
